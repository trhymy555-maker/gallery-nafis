# گالری نفیس — نسخه آماده اتصال و انتشار رایگان

## این نسخه چه کار می‌کند؟
- به Firebase موجود با شناسه `gallery-nafis` وصل است.
- پنل مدیریت از Firebase Authentication و ایمیل `darabinafise@gmail.com` استفاده می‌کند.
- داده‌های جدید را در مجموعه‌های جداگانه `artworks`، `categories` و `siteSettings` نگه می‌دارد؛ مجموعه قبلی `products` حذف یا تغییر داده نمی‌شود.
- برای جلوگیری از نیاز به پلن پولی، آپلود Firebase Storage استفاده نمی‌شود؛ برای هر اثر باید URL مستقیم HTTPS تصویر وارد شود.
- آماده انتشار استاتیک با GitHub Pages.

## مراحل راه‌اندازی
1. کل ZIP را استخراج کن و تمام فایل‌های داخل آن را در ریشه یک مخزن GitHub جدید بارگذاری کن (خود پوشه‌ی اضافی `nafis-final` را به‌عنوان ریشه سایت قرار نده؛ فایل `index.html` باید در ریشه مخزن باشد).
2. در GitHub وارد `Settings > Pages` شو؛ بخش Build and deployment را روی `Deploy from a branch` و شاخه `main` و پوشه `/ (root)` قرار بده و Save کن.
3. بعد از نمایش آدرس سایت، دامنه آن را از `Firebase Console > Authentication > Settings > Authorized domains` به دامنه‌های مجاز اضافه کن؛ برای GitHub Pages معمولاً دامنه `USERNAME.github.io` است. اگر سایت در زیرمسیر یک مخزن باز می‌شود، دامنه همچنان همان `USERNAME.github.io` است.
4. در Firebase Console > Authentication > Sign-in method، روش `Email/Password` را فعال کن. در بخش Users، اگر `darabinafise@gmail.com` وجود ندارد، با Add user همان ایمیل را بساز و یک رمز قوی تعیین کن. اگر حساب از قبل وجود دارد، حساب جدید نساز؛ همان رمز فعلی را استفاده کن یا از فرایند بازیابی رمز بهره ببر.
5. در Firebase Console > Firestore Database > Rules، قواعد فایل `firestore.rules` را بررسی و منتشر کن. این قواعد فقط دسترسی مجموعه‌های جدید را تعریف می‌کنند و دسترسی عمومی به سایر مجموعه‌ها را می‌بندند؛ اگر برنامه دیگری از همین Firestore استفاده می‌کند، پیش از انتشار قواعد، آن قواعد را با هم ادغام کن تا دسترسی آن برنامه ناخواسته قطع نشود.
6. `/admin/` را در سایت باز کن و با ایمیل مدیر و رمز Firebase وارد شو. ابتدا در بخش دسته‌بندی‌ها دسته بساز، سپس آثار را اضافه کن.

## تصاویر آثار بدون هزینه Storage
در پنل، لینک مستقیم HTTPS تصویر را وارد کن. لینک باید مستقیماً به فایل تصویر برسد، نه صفحه وبِ نمایش تصویر. می‌توانی تصاویر را در پوشه‌ای مانند `assets/images/` داخل همین مخزن قرار بده و از URL نهایی GitHub Pages استفاده کنی؛ برای افزودن فایل‌های جدید، مخزن را دوباره به‌روزرسانی کن.

## نکات مهم
- این پروژه مجموعه‌های `artworks`، `categories` و `siteSettings` را استفاده می‌کند. این مجموعه‌ها با `products` قدیمی جدا هستند؛ داده‌های قبلی دست‌نخورده می‌مانند.
- Firebase API key در برنامه وب، شناسه پیکربندی عمومی است؛ امنیت داده‌ها باید با Authentication و Firestore Rules اعمال شود. هرگز رمز عبور یا Service Account Key را در فایل‌های سایت قرار نده.
- این ZIP قواعد را در Firebase خودکار منتشر نمی‌کند؛ انتشار Rules را از کنسول انجام بده و قبل از آن، وابستگی برنامه‌های موجود را بررسی کن.
- فرم تماس فعلاً پیام را برای کپی آماده می‌کند و خودش ایمیل ارسال نمی‌کند.
- GitHub Pages فقط فایل‌های استاتیک را میزبانی می‌کند؛ اجرای JavaScript سمت مرورگر و اتصال مستقیم به Firebase پشتیبانی می‌شود.
